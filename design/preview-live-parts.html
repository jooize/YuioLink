Live parts

Settled this round: the dotted space stays; recipients-as-headline stays; and the costume race is over — your C-with-equals wins. Each fold row becomes a verbatim slice of the URL carrying its own delimiter and its own =: ;sid=9f2c, ?next=…, &subject=Order 4192. No labels, no columns, one cell per row — concatenate the rows and the stored string reassembles. It also quietly beats D at your other wish: a gloss or a pill is a second cell, and second cells are where the clipboard tabs came from.

About "call me": that bare space was the point, not a bug. The card stored &body=call me with a literal space — mailto bodies are one of the few places the canonicaliser lets a raw space survive (probe-verified back in round 14's hazard work). The exact line reproduces stored bytes, so it shows a real space; the dotted underline appears only where display and storage differ. Dotted = was %20; bare = really a space. The subject demonstrated one, the body the other.
The clipboard cannot be styled — but it can be spoken to. Native selection serialises rendered line boxes: every hard line break becomes \n, every table cell boundary a \t. No CSS keeps the plate-over-list-over-rows formatting and yields a clean single string; that is a browser rule, not a layout bug. The single-cell slices already remove the tabs; the newlines need the same small tool the page has used since preview.js: a copy listener. When a selection touches the URI assembly, the handler swaps in the true stored characters for the selected parts — formatting stays, clipboard tells the truth. Without JS nothing breaks: you get the visible text with newlines (which URL bars strip on paste anyway), and the exact line remains the one-element, one-text-node manual copy source.

And your checkbox idea is mocked live below — try it. Untick alice@ or a tracking parameter and watch "After your edits" appear with the rebuilt string (note the delimiter promotion: drop ?next and &q becomes ?q). Copying anywhere in the assembly copies the edited raw string; selecting within a single row copies just that slice, raw. Ground rules for the real build: removal only (a subset of an allowlisted URL is still allowlisted), core slices are not uncheckable (scheme, host, port, path — dropping a port would change which server answers), userinfo/params/fragment are, the button's href is rebuilt from the same parts, and with JS off the checkboxes are simply absent and the link is the stored one. "Exactly as stored" never changes — it is the record; "After your edits" is the tool.
