YuioLink · design note 16

Parts and people

What this round settles, per review of note 15.
  • No lid on tel: — the Premium Rate chip warns; the button sits in the open. The dashed guard stays in reserve only for the spoofing chips (Hidden Characters, Padded With Spaces), where what you read and what you copy differ.
  • Phone numbers are always formatted in the headline — libphonenumber's rendering regardless of how the creator typed it. Nobody suffers a creator's odd hyphens, and "Exactly as stored" carries the truth. The no-spaces guard is retired; padding still gets its chip and its tint in the exact line.
  • Scheme plate colour stays as is — plain text colour, size as its emphasis.
  • The exact line takes the https line's real palette — round 15 was too timid about it; see section 3.
  • https keeps its page. No table by default — instead an optional "Show the parts" fold under the URL line (section 4), which also answers the semicolon question.
  • mailto local parts get full strength — sales@ matters, especially on freemail domains where the local part is the identity (section 2).
  • Confirmed yes: per-recipient to/cc/bcc rows; premium SMS short-code detection; Spotify subtitles from the URI's own type segment; xmpp:?join means a room. Trackers: all listed, never counted — fifteen rows for fifteen trackers is the honest page.
The matrix: claim, checked against the spec. It holds. MSC2312 (the Matrix URI scheme) defines exactly these type segments: u/ for users (sigil @), r/ for room aliases (#), roomid/ for room IDs (!), and e/ for events ($) — the one my note 15 list missed; it nests under a room, as in matrix:r/someroom:example.org/e/EventId. What likely made it look wrong: older drafts used user/, room/, event/, and those still float around — the spec deprecates them (parse, never generate). So the subtitle logic stands, and should accept the legacy spellings too when classifying.

3 · Exactly as stored, in its true colours

Why it looked uncoloured: round 15 only used greys. The https line's palette — the one that reads as syntax — gets its life from .pv-url .pn, which paints the delimiters in the accent colour. Round 15 gave the exact line dim delimiters, bold-grey keys, grey values: structure without hue. This round mirrors the real recipe one size down: delimiters accent, keys secondary, values full text colour, scheme and percent-escapes receded, domains bold. Every card on this page wears it. The one deliberate difference from the https line remains: no wash in the exact line, ever — the wash appears once per page, on the headline.

4 · https stays itself — the parts are an offer

Decision: the https page does not change. The coloured URL line has earned its keep and stays the one register for web links. What it gains is an offer, not a rearrangement: a quiet "Show the parts" fold beneath it, which unfolds the same table every other format gets — and folds back. No JS, chips never hide inside it, and the closed state is today's page to the pixel.

Yes, there is a semicolon — and it is not the dead &-alternative. RFC 3986 lets every path segment carry its own ;key=value parameters ("matrix parameters" — no relation to the chat protocol). The classic in the wild is Java's /page;jsessionid=8A2C…, a session token hiding in the path where nobody looks. There is also the ; that separates values inside mailto: and tel: (;ext=), which the other cards already handle. In the parts table a path parameter gets its own row, keyed with its own mark — ;sid — so the three row species read at a glance: bare keys from the query, ;-keys from the path, # for the fragment.

Found while checking the renderer: render_url in views.rs has no branch for userinfo or an explicit port — alice@ and :8443 are silently absent from today's URL line (and from what ⌘C copies). Keeping the page as-is still means fixing that: both belong in the line, and userinfo earns its red chip.

"A track" is read off the URI's second segment — a published fact, not a prediction — and falls back to "Something in Spotify's catalogue" when the segment is unrecognised. Same trick, same fallback rule, for xmpp: (?join → "A chat room on XMPP", else "An XMPP chat address") and matrix: (u/ a user, r/ / roomid/ a room, e/ an event — legacy user/, room/, event/ accepted when classifying, never generated).
