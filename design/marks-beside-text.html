Marks Beside the Text

The text is drawn once, exactly as stored, and every mark is drawn beside it. The browser measures where each character falls, and the mark is placed there.

1. The problem, live in this browser

Each row draws one word three ways. Plain has no mark. Wrapped is how History and the Text page mark it today: the joiner sits inside its own element, which also draws the wedge. Beside is the proposal: the text is left whole and the wedge is placed over it. Safari draws some Wrapped words differently from Plain. Chromium does too, because of the wedge itself. Each verdict compares a word's width with Plain.

2. How it is built

There are two layers. The text layer is one unbroken run of text, nothing inside it. The mark layer holds one small box per mark, each placed where the browser says that character sits. The marks take the pointer away from nothing: selecting and copying act on the text alone.

3. Every view

A tick, a wedge and the emoji cap take no width, so they can always sit beside the text. A label is different: it writes a hidden character's name into the line on purpose, to show what is there. A label is a rewrite of the line rather than a mark on it, so it stays in the line.

4. What was ruled out

ApproachWhy not
Style the wrapper so it does not split the wordSafari splits at any element, whatever its style. No CSS prevents it.
The browser’s Highlight APIIt colors text without wrapping it, but only glyphs that are drawn. A zero-width character has nothing to color, so there is nothing to put a wedge on.
Wrap the whole word in one elementThe word stays whole, but without measuring, the wedge cannot go to the joiner’s spot inside the word. Only good enough for a page without JavaScript, and there leaving the word alone is simpler.
