YuioLink · design note 2

Reveal: naming, subline, badge, refusal

0 · A finding that rewrites the copy

Every limited link is a one-time link. The API rejects any max_uses other than 1 (web.rs:264: "A link is either unlimited or single-use"), and the create form only offers Public / Secret / One-Time (web.rs:353). So max_uses is only ever NULL or Some(1), and a subline reading "Spends 1 of 3 views" describes a state your system cannot produce. Every option below is written for the one-time reality.

Two consequences fall out of the same fact: badge_text(false) → "Limited Use" is unreachable, as is the non-one-time @else caution in both limited_redirect_block and text_snippet_block (views.rs:959, :977) — limited and one_time are the same condition. And reveal_and_redact blanking the content on the first render is correct, not a multi-use bug, precisely because there is never a second use to serve.

1 · "Reveal Destination" or "Reveal Redirect"?

The consistency you're reaching for is real, but it points the other way.

Keep

Reveal Destination

Names what appears

Both buttons name the thing that appears when you press. For a Text link that is the text; for a Redirect it is the destination. They are already the consistent pair — the noun is the payload, in both.

Reject

Reveal Redirect

Names the link's kind

Now the pair is inconsistent in a way that is easy to miss: "Text" is a payload, "Redirect" is a kind. And it is not true — pressing does not reveal a redirect, it reveals where one goes. The kind is already stated once, in the kicker above ("YuioLink Redirect"); saying it twice on one page spends the word without adding anything.

2 · The subline — six ways to say the price

The label says what you get; the subline says what it costs. It has one shot at the strongest true sentence, so the candidates below trade off finality (it will not open again), exclusivity (nobody else gets one), and mechanism (the server deletes it as you read).

Pick

1 · Mechanism

States what the server does

The only line that is a promise rather than a restriction. It is also literally what happens (reveal_and_redact), and it pre-echoes the revealed page's own "Deleted from the server on this view" — one claim, made twice, kept once. Best fit for a product whose pitch is ephemerality.

Strong

2 · Finality

Short, blunt, memorable

The one people will quote back. Two sentences in a subline is unusual and that is why it lands. Risk: it is a slogan, and slogans age faster than statements of fact.

Strong

3 · Exclusivity

Frames it as yours

Turns a limit into a guarantee, which is the honest reading: the sender chose one-time so that exactly one person would see it. Risk: a visitor who arrives second has already been told 410, so the claim is only ever read by the person for whom it is true.

OK

4 · Plain cost

The literal accounting

Correct and unmemorable. "Spends" is the internal verb (hits, max_uses) leaking into visitor copy — nobody outside the codebase thinks of a link as having a balance.

OK

5 · Consequence

What you must do about it

The only option that tells the visitor what to do, and the refresh trap is the one way people actually lose content here. Risk: it is an instruction before the fact, on a button they have not pressed — mild pressure, and slightly long.

Reject

6 · Counted

The one you asked for

Unshippable: multi-use links do not exist (see finding above). It would also leak whether someone got there first, which the 410 currently reveals only after the fact.

3 · What happens to "Opens Once"

Your two instincts — drop it, or keep it and colour it — are both live. Shown in full context so the repetition (or its absence) is visible.

A

Badge dropped

Subline is the only statement example.com

Expires in 6 days

Cleanest. Loses: the link's shape is now only legible to someone who reads the button's second line — there is no at-a-glance mark, and nothing for the eye to catch before the decision.

B

Badge kept, neutral

Today's pill, below the button example.com
Opens Once

Expires in 6 days

Says the same thing twice, three lines apart, in a quieter voice the second time. This is the weakest option — repetition without emphasis reads as redundancy, not reinforcement.

C

Badge coloured, above

One-Time purple, before the button example.com
Opens Once

Expires in 6 days

The colour is not new: --c-once is what the create picker and the stats page already use for One-Time. Borrowing it makes the badge recognition rather than decoration, and above the button it arrives before the decision. The subline then explains what the badge asserts, instead of echoing it.

D

Badge into the kicker

Folded into the page heading

YuioLink Redirect · Opens Once

example.com

Expires in 6 days

Most economical — no extra element at all. Loses: the kicker is deliberately quiet (14px, secondary), and one-time-ness is the loudest fact on the page. Putting it there files it as metadata.

Recommended: C. It answers your "coloured border for attention" directly, but takes the colour from the system instead of inventing one — and moving the badge above the button converts the duplication into a sequence: what this link is (badge), then what pressing does (subline).

4 · When the stored destination fails validation

The state you asked to see. It should be unreachable — creation validates — so this is what a bug, a bad migration, or a hand-edited row would surface as. The rule: printing a URL is always safe, linking it is not, so the address stays on screen and only the control goes away.

Recommended

Print it, inert

No anchor, no button, address still shown javascript:alert(1)

YuioLink won't open this. The address stored for this name isn't a web address — it's an instruction for your browser, which a link should never be. It's printed above so you can see exactly what was here.

Expires in 6 days

No Continue button at all — not a disabled one. A disabled button implies "not yet"; this is never. The visitor loses nothing: they can still read, select and copy the address, and decide for themselves.

Rejected

Withhold it

Refuse and show nothing

YuioLink won't open this. The address stored for this name isn't a web address that can be opened.

Expires in 6 days

Hides evidence from the one person positioned to report it, and the whole page exists to show people what a link really is. Withholding here contradicts that on the single occasion it matters most. Note the asymmetry: a limited link withholds its destination because it is secret; this one would be withheld because it is dangerous — and danger is the case for showing, not hiding.
