A hostless URL, coloured like a URL

You're right about the arrow, and I had it wrong twice. openIcon's path is M2.5 10.5 10.5 2.5 — a diagonal shaft — plus M4 2.5h6.5V9, which is a corner arrowhead, not a box. The comment above it ("the arrow out of a box's corner") describes the arrowhead's shape and misled me; I should have read the path the first time. So the history row uses a bare arrow, the boxed glyph is unused anywhere in the codebase, and tier 2 can claim it with no conflict at all — cleaner than the "honest tension" I talked myself into last round.

"Write to" over "Email", applied throughout.

1 · The same grammar, after the colon

An http preview already grades a URL by part: scheme tertiary, domain highlighted, path and query values distinguished. Everything after scheme: has the same kind of structure — delimiters, keys, values, and sometimes a domain — so it gets the same four classes rather than new ones.

The parts

All four already exist in app.css
@ ? & = : Delimiters — structure, tertiary xt Keys, local parts, segments — secondary urn:btih:c12fe3… The value being checked — full text example.com A registrable domain — accent highlight

The domain rule is the one that earns its keep. An address in a mailto: has a registrable domain in it, and a lookalike there does exactly what a lookalike in a host does — decides who you are really writing to. Highlighting it in both places means a visitor learns to check one thing, not two.

What it costs to build

Less than it looks

The url crate already splits a hostless URL for us: Url::parse("magnet:?xt=…&dn=…") hands back query() ready to iterate as key/value pairs, and mailto:hello@example.com puts the address in path(). The only new logic is a rsplit_once('@') for address-shaped bodies and the existing registrable-domain lookup, which urlview already performs for hosts.

Nothing here needs a new stylesheet rule either — .dl is the one addition, and it could equally reuse .sch's tertiary colour.

2 · Every shape of body

mailto

Local part, domain, query
mailto: hello@example.com
mailto: sales@example.com?subject=Order 4192

The domain is the only highlighted thing, exactly as on a web preview. A subject line is a value, so it reads at full strength — it is content someone is about to send in your name.

magnet

Query pairs, no host at all
magnet: ?xt=urn:btih:c12fe3…9ab4&dn=ubuntu-24.04

The wall of hash finally has shape: xt and dn recede as the labels they are, and dn — the display name, the only human-readable claim a magnet makes about itself — stands out where it always deserved to.

tel · sms

One value, nothing to grade
tel: +47 800 12 345
sms: +47 800 12 345?body=STOP

Degrades to plain text when there is no structure, which is correct — the colouring must never invent divisions that are not there. The sms: body is worth surfacing: a pre-filled message is the closest thing on this list to something being sent in your name.

spotify · matrix

Colon-separated segments
spotify: track:4uLU6hMCjMI75M1A2tKUQC
matrix: r/rust:matrix.org

A matrix: address carries a homeserver, which is a registrable domain and gets the highlight — the same question again, in a fourth place.

xmpp · irc

Address- and host-shaped
xmpp: jooize@example.org
irc: //irc.libera.chat/#rust

irc: and ftp: have real hosts, so they already flow through the existing host path — they are hostless only in the sense that they are not http. Nothing special needed.

3 · The fallback label

For schemes with no everyday verb. Your format, plus the neighbours worth seeing next to it.

Pick

Open Link · magnet:

Open Link · magnet: A file identified by its hash

The action leads, the scheme trails as a tag in mono — an identifier styled as one, not a word in a sentence. It also matches the lid's separator, so the middot means the same thing in both places: here is the qualifier.

Open Special Link · magnet:

Open Special Link · magnet: A file identified by its hash

Yours as written. Against: "Special" is a judgement without content — and the lid directly above has already said "Not a web address", which is the same claim made precisely. Two hedges before the verb.

Open · magnet:

Open · magnet: A file identified by its hash

Tightest. Against: "Open" alone leaves the button without an object, and every other button on the site names what it acts on.
