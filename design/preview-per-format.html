YuioLink · design note 15

Each format at its best

What this round changes, per review of note 14.
  • Flags are emoji now — 🇳🇴 costs no characters of copy and is the one place an emoji earns its keep. On platforms without flag glyphs it degrades to the letters NO; the country name beside it carries the content either way.
  • The extension joins the number. ;ext=4021 is part of dialling, not a payload parameter — so it rides the headline as ext. 4021, which is libphonenumber's own rendering. The tel: table is gone entirely.
  • The row tags are retired. identifies / name only / sent as you shouted in uppercase what the note under the table already says in a sentence. The notes stay; the tags go.
  • "Exactly as stored" gets the site's own syntax colours — the .pv-url palette one size down, and a sentence-case italic label instead of the uppercase one. It never collapses, at any length: it is the copy target and the proof.
  • The lid is gone from the common case — argued in full below. Where a chip burned red, a guard remains, but as a plain disclosure line, not a drained fake button.
  • sms: gets the same chips as tel: — same numbers, same tables, same hazards.

3 · The button question, answered

Recommendation: no lid in the common case; a guard only where a chip burned red.

"Show…" was confusing because it was answering a question nobody asked. Walk the flow: the visitor already chose to follow a YuioLink; this page is the safety step — the whole card exists so nothing happens before they have seen everything. On a one-time link they have additionally pressed Reveal, a deliberate POST. By the time the amber button is on screen, pressing it is the third intentional act, it does nothing destructive (the use was spent by Reveal, not by this anchor), and its two lines already say what it is and what it does. A second gate on top of that is not caution — it is friction that trains reflexive double-clicking, which is worse than no gate. And the drained clone had a deeper problem than its label: a greyed-out button reads as a disabled button, i.e. "broken", not "armed".

Where something is wrong — Premium Rate, Hidden Characters, Padded With Spaces — a pause is honest, so a guard stays. But shaped as what it is: a plain dashed disclosure line reading "Show the Call button" — naming the exact thing that will appear, sitting beside the chip that justifies it (card 1 above). It cannot be mistaken for the action, because it does not look like a button; it opens without JS; and the real button lands where the line was — no grid, no ::details-content trap, nothing to animate.

If a universal lid is wanted after all, the same line works everywhere ("Show the button"), but I would not ship it: the pages above are calmer and more honest without it.

4 · http(s) with the same table

Every part a URL can carry, and where each one goes. https://alice:hunter2@login.example.co.uk:8443/reset/9f2c?next=…&theme=dark#step-2
  • scheme → the plate, same as every other format. Plain http keeps the settled treatment: red scheme characters, open padlock, Not Encrypted chip.
  • username / password → table rows plus a red chip. Text before the @ is the oldest disguise a URL has (https://bbc.co.uk@evil.example/), and a password embedded in a shared link is worth a red chip in its own right. Shown verbatim — it is stored content like everything else.
  • host → the headline: subdomain dim, registrable domain bold on the accent wash, exactly as today. IDN mixed-script keeps its existing red panel.
  • port → rides the headline, dim, like a phone extension rides its number. The url crate never serialises default ports, so if one is visible it is non-standard by definition — the dim :8443 is itself the signal.
  • path → first table row, percent-decoded for reading.
  • query → one row per pair, repeated keys repeated, order preserved — the magnet treatment exactly.
  • fragment → last row, keyed #. Never sent to the site; the browser keeps it for the page.

The case for unifying, in one card. No userinfo, no port, no query, no fragment — so no chips, no note, and a one-row table. The cost of the unification is this card versus today's .pv-host + .pv-url page, and the difference is small; the gains are one renderer for every scheme, one copy target everywhere ("Exactly as stored" inherits pv-url's ⌘C-and-checkmark), long paths that wrap in a row instead of snaking through a centred line, and http(s) finally getting hazard chips like everyone else. I would unify.

5 · Ideas beyond the brief

  • ⌘C moves to the exact line. .pv-url today owns the copy handler and the trailing green ✓; in the unified layout the exact line is the string worth copying, so the handler and the checkmark move there with it.
  • Spotify can sharpen its subtitle from its own URI. spotify:track:… / album / playlist / artist is right there in the second segment: "A track in Spotify's catalogue" is a published fact, not a prediction, and beats the generic "Something in Spotify's catalogue" whenever the segment is recognised.
  • Same trick for chat schemes. xmpp: with ?join is a room, not a person; matrix: paths start u/ (user), r/ (room), roomid/. The subtitle can say which without guessing.
  • mailto with several recipients gets one row per address — to / to / cc / bcc — the repeated-key treatment magnet already established. A cc full of strangers is worth seeing before your mail app opens.
  • Short codes are the sms trap worth catching. libphonenumber's short-number metadata knows premium SMS codes; when the crate lands, the Premium Rate chip should fire for those too — that is the subscription scam, and it is a table lookup away.
  • Trackers could be counted instead of listed when a magnet carries many: first two rows, then a plain tr row reading "6 more trackers". The exact line still carries all of them, so nothing is hidden — but I would hold this until a real magnet proves the need; the two-tracker card above is fine as is.
