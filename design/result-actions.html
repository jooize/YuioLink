On Trash specifically. History's trash opens a confirm offering two very different outs — Forget Link (drop it from this device) and Delete Link (remove it from the server, possible only while the creation token is held). On the result, Forget is meaningless — the link was created one second ago and forgetting it would just erase the row you are looking at — so the result's trash can only sensibly mean Delete, with the confirm shown in R1–R3. That is a real action worth having (you pasted the wrong URL and want the link to stop resolving before you send it anywhere), but it is also the one action on this page that cannot be undone, sitting next to the one you tap most. If it ships, it belongs at the edge of the cluster, never between Copy and Preview.

Deleting does not free the name. delete_link sets withdrawn = 1 and keeps the row, so the name stays reserved until the link would have expired anyway — it answers 410, never 404, and can never be re-registered in the meantime. So the confirm should not promise a name back. “Stop this link working?” is the honest prompt; the name is spent either way.
