Drafts and digits

Your round-25 review — five verdicts applied to the gallery, one pick left open.
  • Split button: adopted. Every action button in the gallery is now a split — thirteen of them, tier 1 and tier 2 alike — amber-or-blue action plus a blue Copy segment that copies exactly what the button would open, checkbox edits included. Reveal stays whole (there is nothing to copy before the spend), and the refusal still has no button at all.
  • The Draft rule: you were right again. RFC 6068 needs no address anywhere — a bare mailto:?subject=… opens a compose — so the floor is gone entirely and nothing ever locks. Empty the address list and the button becomes "Draft a Message" / "An email with no recipient". Applied consistently: the single-address card's "core like a host" exception is dead too — its address is a removable slice like any other, because an address is content, not routing. Both live in the gallery. One asymmetry, from the grammars: sms keeps a floor of one — RFC 5724's grammar requires at least one recipient (sms-recipient *("," sms-recipient)), so the last number still locks. mailto drafts; sms does not.
  • The chevron: real fix, not a bigger margin. You meant copying — and the space was never the real bug: the ▸ was ordinary text, so selection dragged it into the clipboard as "▸Show the parts". It is now generated content (::before), which selection and copy never pick up, and that freed it to behave like a control: 14px, and it rotates to ▾ when the fold opens. Kept over a pure relabel because the label already relabels ("Show the parts" / "Hide the parts") — the chevron's job is to look foldable before you commit, and now it also confirms after.
  • One-time wording: yours verbatim. "The destination is shown when revealed." — states what will happen instead of implying we hold something back; the server genuinely has not disclosed anything yet.
  • The path stays fixed — and your own "noise" instinct is the reason. The editing machinery exists to strip what rides along a link: trackers, session ids, userinfo, prefilled words. The path is not along for the ride — it is the destination; removing it doesn't clean this link, it aims at a different page. And since nearly every URL has a path, a removable path would put a checkbox on virtually every https view — the everyday page would never again be the quiet card the fold rule just won back. The disabled row already says "seen, and not yours to change".
  • Open pick below: phone syntax highlighting (A or B), with your one-number-per-line list shown in both.

1 · Phone syntax — two dresses for the same number

A · Recommended

The routing recedes

Country code secondary · separators tertiary · national digits bold tel: +46 70-123 45 67
🇸🇪 Sweden Mobile

The same recipe as every other headline: the part that routes (+46, like a scheme or a subdomain) steps back, the part a person recognises — the national number, the shape locals write as 070-123 45 67 — keeps the bold. The hyphen dims like any delimiter. Nothing is lost: the flag chip already names the country at full strength.

B

Only the separators recede

Every digit equal · punctuation tertiary tel: +46 70-123 45 67
🇸🇪 Sweden Mobile

The lighter touch: all digits carry the same weight, only the punctuation drops to tertiary. Safer if you feel +46 is part of what a visitor should verify at full attention (it does decide which country's 70 this is). The cost: the headline stays a near-uniform block, and the card's one typographic idea — recede what routes, bold what identifies — goes unused here.

One number per line, no commas in the display — the comma-joined run read messy, and a phone headline owes selection nothing: it is a rendering (libphonenumber's), the exact line and the slices carry the stored +46…,+47… truth, so the stack is free to be readable. Each line wears the highlight (option A here; it follows whichever you pick). And the floor is back for sms only, on the standard's authority: RFC 5724's grammar requires at least one recipient, so untick either number and the other locks — mailto drafts, sms cannot. The mailto list stays a comma-joined inline run for now: it is character-identical to the stored list by design (the round-20 selection trick), though it wraps one-address-per-line on phones anyway. Say the word if you want mail stacked too, at the cost of that identity.
