Redirect vs Text — a control that works everywhere

Paste https://example.com and the server stores a Redirect. To store that same URL as a Text snippet instead, the only override today is holding ⌥, announced in a title tooltip. That is desktop-with-JavaScript only: there is no Option key on a phone and no hover to reveal the tooltip, and with JavaScript off there is no override at all. Two of the three contexts cannot reach the feature.

Anything chosen here has to be a real form control, so a plain POST / carries it. The server side is nearly free either way — create_link already takes a kind, and web.rs already maps None | "" | "auto" to detection; the form path just has to stop passing None. In every option below the ⌥ shortcut survives as a desktop accelerator.

Each option is shown with a URL in the field, since that is the only case where the control changes the outcome — a non-URL is Text no matter what.

A · Split button, second half submits

Two real submit buttons in one form. Browsers send only the clicked button's name/value, so kind=text arrives with zero JavaScript and is one tap on a phone.

Cost: the override is permanently on screen at full button weight, competing with the primary action for a case that is rare. It also collides with the existing "Clear" button, which occupies this slot once JavaScript loads — one of the two has to move.

B · Quiet secondary underneath

Same two-submit-buttons mechanism, but the override sits below the primary at outline weight, so the hierarchy is unambiguous. With JavaScript it can hide itself whenever the content is not a URL — where it would change nothing — and appear only when it matters.

Cost: a second full-width control in a column that is already tall; without JavaScript it is always visible, including for plain text where it is a no-op.

C · Checkbox

The plainest possible form control: <input type="checkbox" name="as_text">. Posts natively, needs no second button, and its state is visible before submitting rather than being a property of how you clicked.

Cost: it reads as a setting rather than an action, and the primary button then has to agree with it — the label must flip to "Create Text Link" when it is ticked, which is JavaScript work for a control whose whole appeal was not needing any.

D · A Kind picker, matching the Type picker

The idiom already on the page: a segmented control with a legend. Three radios — Auto, Redirect, Text — where Auto is the default and does exactly what happens today. Fully native, and it makes the detection visible instead of magic.

Cost: the heaviest option. It adds a whole control row for a decision the server gets right almost every time, and it invites the user to think about a distinction they mostly should not have to.

E · One line of prose with a link in it

A sentence that states what will happen and offers the alternative, the way the type disclosure already talks. The alternative is a real submit button styled as a link, so it still posts without JavaScript.

Cost: an underlined word is a weak affordance for an action that creates something; some people will not read it. It is also the least discoverable option for the person who does not already know Text links exist.

F · Caret menu (native <details>)

The classic split-with-menu: primary action plus a caret that opens alternatives. Built on <details>, it opens and closes with no JavaScript, and the item inside is a submit button. Scales if a third choice ever appears.

Cost: the most machinery for the fewest options — a menu holding one item is a menu that did not need to exist. Menus over a form also need care so opening one does not submit or lose focus on mobile.

G · Name the detection, offer the flip

Rather than adding a control, surface the decision the server already made and let it be corrected: "Detected: Redirect — make it Text". It teaches what the two kinds are at the moment the distinction is live, which no other option does.

Cost: still a link-weight affordance, and the line is a permanent piece of chrome explaining something most people never need explained.

H · Do nothing on the page; fix it on the result

Leave creation alone and put the correction after the fact: the result panel gains "Not what you wanted? Make it a Text link instead", which re-creates the link as Text and withdraws the redirect. The common path stays completely uncluttered.

Cost: it burns a name and a round trip to fix, and the offer arrives after the link has been created — which for a one-time link is exactly the wrong moment. Included because it is the only option that adds nothing to the form.

Worth deciding first

How often does someone actually want a URL stored as Text? If it is genuinely rare, B or G is right: present but subordinate, and hidden by JavaScript whenever the content is not a URL. If it turns out to be common — the /stats page will tell you, since it counts Redirect and Text creations separately — then D stops looking heavy and starts looking like the honest shape of the form.

Whatever wins, the field posts kind and the server stops passing None on the form path. That plumbing is the same for all eight.
